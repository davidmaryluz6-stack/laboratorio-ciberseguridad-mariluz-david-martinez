 [DICTAMEN FORENSE - DIFERENCIACIÓN TÉCNICA CLAVE]
   ⚠️  RECIBIR HTTP 200 != AUTENTICARSE SATISFACTORIAMENTE
   1. Causa técnica del HTTP 200:
      El servidor perimetral no tiene activo un middleware de autenticación
      en la ruta '/'. El servidor ignora cabeceras Authorization no solicitadas
      y devuelve el panel público 200 OK.
   2. En un servicio realmente protegido (ej. /admin o /login):
      - Credenciales incorrectas deben generar: HTTP 401 Unauthorized.
      - Credenciales correctas generan: HTTP 200 OK con token de sesión.
   3. Mitigaciones indispensables para proteger endpoints de autenticación:
       - Desafíos CAPTCHA adaptativos.
       - Rate Limiting estricto en rutas de autenticación.
       - Bloqueo temporal por intentos fallidos (Account Lockout).
       - Autenticación Multifactor (MFA).
